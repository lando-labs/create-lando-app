## Post-Sprint (2026-07-18)
Built by the `nextjs-lando-ds` agent (v1.1.0, MCP-driven), then verified in a real
browser + the live smoke test. The browser pass earned its keep — it caught **four
bugs that passed the agent's own review**:

1. **Runtime crash** — `color.ts` imported `hexToOklch`/`oklchToHex` from the DS but
   never re-exported them; `Controls.tsx` imported them from `./color` → `oklchToHex
   is not a function`. Fixed by re-exporting the DS maths from the one colour module.
2. **Invisible controls** — the agent used hallucinated `--spacing-px-32/40/48`
   tokens (don't exist in the DS); the colour well collapsed to 12px and the
   quick-start dots to ~2px. Swapped to explicit rem (intrinsic affordance size).
3. **Well fought the user** — the native colour input was bound to the *corrected*
   hex, so picking a failing colour snapped the swatch away from the pick while the
   text field showed the original. Rebound to the raw input; the preview reflects the
   safe output; the "Fix contrast" button bridges them.
4. **Misleading preview** — `Button variant="secondary"` is a neutral grey in the DS
   (doesn't consume `--color-secondary`), so it misrepresented the secondary brand
   colour. Replaced with a truthful Primary/Secondary/Accent `ColorSwatch` trio + a
   real `primary` Button as proof the tokens flow.

Verified live (localhost:7711, DS 0.57.0): a11y auto-correct (`#FFEE00` → `#877400`
@4.64:1, hue preserved) + "Fix contrast"; pass badge; 5 quick-start swatches; 3 ramp
chips with deterministic secondary/accent (Opposite = primary+180°); optional pinned
secondary; OKLCH `@layer app` CodeBlock w/ copy (no error override); harmonised
semantic Alerts with Error staying red; light + dark; **no hydration/console errors**.
