## Overview
- **Branch**: `sprint/v0.1.0-rich-preview`
- **Target Version**: 0.1.0 groundwork (merges to main; no release — v0.1.0 ships at launch)
- **Focus Area**: The getting-started page — a live, comparison-first theme preview
- **Estimated Scope**: **Medium–Large** — theming architecture change + preview rebuild

## Why
DS #11 (scoped `ThemeScope` re-derives the tonal ramp + interaction-state tokens)
landed in `next` → 0.59.0. That unblocks the richer preview we deferred in #34,
where we chose page-level `:root` theming *specifically to work around* the bug.

Owner's design (#36): the page runs a neutral **slate baseline**; a scoped
**preview area** shows the user's theme with its **own light/dark toggle**; an
**"apply to page"** toggle reskins the page ("see it live"). The slate page around
the preview is the baseline, so the comparison is implicit — no DS-default panels.

## Phase 0 — VERIFIED ✅ (2026-07-24)
Before building on it, proved DS #11 empirically rather than trusting the changelog:
a throwaway probe rendered two `ThemeScope`s with different primaries (#C2410C /
#0F766E). **PASS** — each scope derived its own ramp family, including `hover` and
`active`. Under the old bug both rows would have been identical grey.
Verified step names: `lightest, lighter, light, dark, darker, darkest, hover, active`
(+ base = `var(--color-primary)`), for `primary` and `secondary`.
