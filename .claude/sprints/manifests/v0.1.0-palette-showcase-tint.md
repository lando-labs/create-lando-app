## Why
Post-#31 the page composes well but shows only the 3 base swatches, and the
light/dark toggle is pure white/black — the brand never reaches the surfaces. Owner
wants the page to showcase the colour *system*: the full derived ramps, and
theme-adjacent (brand-tinted) light + dark. Both make it a stronger DS storefront.

## Acceptance Criteria
**A — Full palette showcase (#32.1)**

**B — Brand-tinted light + dark (#32.2)**
- [ ] Opt-in tint control: **None / Subtle / More** (SegmentedControl). Default: Subtle

- [ ] Tinting colours **both** modes: emits **mode-scoped** overrides into `@layer app`
  (`:root[data-theme="light"]` + `:root[data-theme="dark"]`).
- [ ] Recipe: per surface token, **preserve L, set H = primary hue, add small C scaled

- [ ] The emitted `@layer app` block reflects the tint (so paste = what you see). When
  tint = None, no surface overrides are emitted (base snippet stays small).

## Post-Sprint (2026-07-18)
Built by the main loop (engine correctness + design-sensitive, so hand-driven, not an
agent) with a tight browser loop. Both asks landed:

- **Palette showcase** — `PaletteRamps.tsx` renders each role as a continuous 5-step
  ramp bar reading `var(--color-<role>-<step>)`, plus a Surfaces row. Live, error red.
- **Brand-tinted themes** — a None/Subtle/More `SegmentedControl`; the engine derives
  tinted surfaces (L preserved → contrast holds, H→brand, C→strength) and `emitLayerApp`
  writes mode-scoped `:root[data-theme=light|dark]` blocks (only when tint ≠ none). A
  "Your surfaces, this mode" mini-panel in the preview makes the tint *legible* (warm
  charcoal / warm cream for a warm brand), which the abstract swatch row alone did not.

**Browser-caught this pass:**
1. **CodeBlock highlighter injected a stray `;`** into quoted attribute selectors, so
   the emitted CSS *displayed* as `data-theme=';light'` — looked broken on the one thing
   users copy. Switched to unquoted `[data-theme=light]` (valid CSS, identical) to dodge it.
2. **`next build` type error dev mode hid:** `Text size` only accepts `sm|md|lg` (not
   `xs`, unlike `Heading`). Three new captions used `xs` → dropped to `sm`. Also a reminder
   that the dev preview compiles looser than `next build` — ran `tsc --noEmit` to sweep.
3. The fish `cmd | tee | tail; echo $status` trap struck again — the first "smoke passed"
   was `tail`'s exit, not npm's; the build had actually failed. Re-ran capturing the real
   status. See [[verify-the-verification]].

**Decision to confirm with owner:** default tint = **Subtle** (shows the feature on load,
but every scaffold's emitted CSS then carries surface overrides). `None` keeps the base
snippet minimal.

Verified live (localhost:7711, DS 0.57.0): ramps for all roles; tint None/Subtle/More;
both modes tinted warm/cool; None reverts + emits no surface block; contrast preserved;
mobile single-column, no overflow; no console/hydration errors. **Smoke: green.**
