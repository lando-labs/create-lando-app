### Deliberate scope calls
- **MCP package name held, then resolved by fact.** Mid-sprint the name was
  deliberately left as `@lando-labs/design-system-mcp` + `TODO(#16)` rather than
  guessed at — a blind find/replace would have silently invented a name. The MCP
  then **published as `@lando-labs/lando-ds-mcp@4.0.0`**, so it was wired from
  its own README (server key `lando-ds`) and **verified with a live handshake**
  instead of assumed. Waiting cost nothing; guessing would have shipped a wrong
  name into every scaffold.
- **Historical records left alone** — the archived manifest and the 2026-07-12
  plan were accurate as written; only living docs were migrated.
- **"Ask your AI to confirm setup" line deferred to Sprint 2** — the brief/agent
  don't exist yet and the MCP can't respond; the hint ships with its artifacts.

### Lessons Learned
- **The blind rename was the danger, not the work.** Two real traps: (1)
  `smoke.mjs` built the node_modules path from *split strings*
  (`'@lando-labs', 'design-system'`), invisible to a slash-based find/replace —
  the #462 assertion would have silently checked the wrong directory; (2) the
  replace corrupted prose that *intentionally* named the old package, producing
  self-contradictions like "`lando-ds` never shipped publicly". A negative
  lookahead protected the MCP name; the rest needed human-level reading.
- **Verify the verification.** A `for f in $FILES` loop silently did nothing
  under fish (no word-splitting) *and* the confirming grep hit the same bug,
  printing a false "none ✓". Only a fresh `git status` caught that zero files
  had changed. Same class of trap: `$status` after a pipe is the last command's.
- The A1-gate framing was baked through the docs; retiring it was as much of the
  migration as the rename.

### Risk flagged for #16 — RESOLVED in-sprint ✅
Flagged: `.mcp.json` written by default would point at an **unpublished** MCP,
showing a failed server in every scaffolded app. **The MCP then published**
(`@lando-labs/lando-ds-mcp@4.0.0`), so the scaffold now points at a real package,
wired per the MCP's README (server key `lando-ds`).

**Verified, not assumed** — spawned the exact command the scaffold writes and ran
an MCP `initialize` handshake: responded `lando-ds v4.0.0`; capabilities tools/
resources/prompts; 127 components, 19 hooks, 15 tools; backed by
`@lando-labs/lando-ds-meta v0.57.0` (matching our `DS_VERSION ^0.57.0`).

Both halves of the dependency chain (DS + MCP) are public. Nothing in epic #17
is externally blocked. Remaining for #16: fold an MCP-resolution assertion into
the smoke test (a working probe harness exists).
